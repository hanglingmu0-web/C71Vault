# C71 Vault — Windows 0.5.3 / Android 0.5.0

Windows 0.5.3では、MIDI保存後にPCの一覧へ反映されない不具合を修正しました。署名付き保存完了記録と前回USBで取得した履歴を再起動後にも表示します。最新の保存履歴取得と復元にはC71をPCへUSB接続し、C71側のUSB受付を開始してください。通常起動にUSB接続は不要です。ドラッグ＆ドロップと自己テストの修正も含みます。Android APKは0.5.0のままです。

C71の空き容量を、過去の版をPCから削除・上書きできない暗号化バックアップに使います。WindowsアプリとAndroidアプリをUSBケーブルで接続します。インターネット、Wi-Fi、Bluetooth、ADBは転送に使用しません。

## 0.5.0の操作

PCでは複数ファイル・フォルダを選択またはドラッグ＆ドロップし、転送方式を選んで開始します。C71ではアプリ内の保存フォルダと受信方式を選びます。[操作ガイド](TRANSFER_UI.md)を参照してください。

## 起動

Windowsでは `start.cmd` または `windows/C71Vault-0.5.3/C71Vault.exe` を開きます。Pythonの追加インストールは不要です。`_internal` フォルダをEXEと一緒に保管してください。別PCへ渡す場合もフォルダ全体をコピーします。

Androidの配布ファイルは `C71Vault-0.5.0.apk` です。0.1から同じ署名で上書き更新でき、既存データは維持されます。Windows版は未署名、APKは本プロジェクトの専用証明書で署名しています。

0.4.0では「MIDI/絶縁通信受付」を追加しました。MIDI 1.0 SysExに7-bit化したデータを入れ、CRC・sequence・サイズ・SHA-256を検証します。診断データは保存せず、**登録済みPCが署名した暗号化バックアップは、staging・保存後の読み戻し・commitまで行います。** USB MIDI入力とUSBシリアル経由のSysEx入力を用意しています。実機では後者をR3/R4で確認しました。フォトカプラによる物理絶縁、MIDI UARTの実配線は未実施です。仕様と接続手順は [MIDI_SYSEX.md](MIDI_SYSEX.md)、R3/R4スケッチは [arduino/README.md](arduino/README.md)、確認済みの範囲は [VALIDATION.md](VALIDATION.md) を参照してください。

現在のWindows EXEは転送画面からMIDIを送信できます。ソースZIP内には`desktop/midi_send.py`もあります。送信のみを成功扱いせず、署名付き保存完了ACKとC71の`保存完了・読み戻しSHA-256一致・commit済み`を確認してください。

2026-09-30の配線試験では、**PS817C（部品刻印による識別）のフォトカプラ2個**を使用しました。往路データ用と復路ACK用に各1個、各LED側に330Ωを2本直列（660Ω）、各受光側に2kΩのプルアップ抵抗を使ったブレッドボード回路です。この構成で18バイト・1KiB・64KiBの往復が9,600 baudで一致しました。**同じPS817C試作回路の31,250 baud試験ではバイト欠落・破損が発生し、未解決です。** この結果だけからPS817C単体の速度限界や故障原因を断定していません。現在の実機は検証用9,600 baud、USB側は115200です。上の0.4.0時点の記録とは区別し、最新の確認範囲は [VALIDATION.md](VALIDATION.md) を参照してください。

0.3.1では、白黒・4色の両光学受付画面を **上段：ACKコード、下段：前面カメラ映像** に変更しました。C71を通常の縦向きで持ち、上段のACKをPC画面上部のカメラへ向けます。

このPCとC71は初回登録・転送フォルダ設定済みです。Windowsアプリを開き、「バックアップ」の手順から使えます。以下の初期設定手順は別のPC・端末で使う場合のものです。

0.3では4色光学転送から復元までを実機で検証しています。検証用の「4色光学実機試験・生成データ」も保存履歴にあります。

## 最初の設定

1. C71をUSBで接続し、ロック解除します。USBの用途を「ファイル転送」にします。
2. C71の「C71 Vault」を開き、「転送フォルダを選ぶ」で内部ストレージの `Documents/C71Vault` を選びます。フォルダがない場合は作成します。「USB受付を開始」を押します。
3. Windowsで「端末を確認・初回登録」を押します。表示された端末の署名鍵がC71画面と一致することを確認します。
4. 続いてC71にPCの登録要求が表示されます。Windowsのログにある「PC鍵」と一致することを確認し、C71で「このPCを登録」を押します。
5. 保護運用ではC71の設定で **USBデバッグをOFF** にしてください。開発用ADB接続はアプリのデータ消去が可能なため、保護の前提から外れます。今後アプリ開発をする際は再びONにできます。

再起動やアプリ終了後はC71側で受付を開始してください。初回登録は同じWindowsユーザー・同じC71なら繰り返す必要はありません。接続を外したりロックしたりして転送が止まった場合は、成功表示を確認するまで未完了として扱います。

## バックアップ

1. 「対象フォルダ」を選びます。編集中の文書は保存し、対象アプリを閉じます。
2. 「復元鍵を新規作成」で `.c71key` ファイルを作ります。**対象フォルダの外**に保存してください。この鍵は暗号化されていない秘密鍵ファイルです。安全な別媒体等にもコピーして保管します。
3. 保存名を入力し、「バックアップ開始」を押します。
   初めて使う復元鍵は、C71の「復元鍵をC71に保管（端末認証）」で承認します。C71が暗号化された鍵を復号して鍵IDと一致することを検証してから保管します。鍵保管が確認できないとUSBバックアップは開始しません。同じ鍵での次回以降は再保管不要です。
4. **「保存完了・C71で照合済み」まで待ちます。** C71側の保存・読み戻しSHA-256照合と、署名付き応答の確認後に表示します。USBへ送っただけでは成功にしません。

各回、フォルダ全体の新しい版を保存します。過去の版は自動削除しません。鍵は次回も同じものを選べます。鍵を変更した版の復元には、その版に対応する鍵が必要です。

## 復元

MIDIで保存した版もUSBから復元します。C71をR4から外してPCへUSB接続し、ロック解除・USBの「ファイル転送」を有効にして、通常版C71 VaultでUSB受信を開始します。PCの「保存履歴・復元・鍵・USB初回登録」タブで「履歴を更新」を押してください。PCに表示されるMIDI保存完了記録はACKの記録であり、C71の現在の一覧はUSBで照合します。

1. C71を接続し、受付を開始します。Windowsで「履歴を更新」を押します。
2. 復元したい版に対応する `.c71key` を選び、保存履歴から版を選択します。
3. 「選択した版を復元」で保存先を選びます。新しい `C71復元_日時` フォルダに復元し、既存ファイルは上書きしません。
4. 暗号の認証と全ファイルのSHA-256照合が完了すると、復元完了を表示します。重要な文書は実際に開いて確認してください。

PCを初期化した場合、新しいWindows環境をC71で登録して保存履歴を読み込みます。版を選び「選択版の鍵をC71から回収」を押し、C71で端末認証すると、鍵を新しいPCに回収できます。**元のPCの認証鍵や鍵ファイルは不要です。ただし、その復元鍵を事前にC71へ保管済みである必要があります。** 0.1で作った鍵は、PCに残っているうちに「復元鍵をC71に保管」で追加してください。

回収するPCは初期化・駆除済みの環境にしてください。鍵の保管ファイルはC71の専用領域にあり、通常のMTPからは見えません。回収時も一時的なPC公開鍵で包み直すため、USB転送フォルダには平文の鍵を置きません。新しいPCでだけ `.c71key` に復号して保存します。

暗号化ファイル `.c71b` と復元鍵を別に保有していれば「手元の .c71b を復元」からC71なしでも復元できます。

## 容量と削除

| 項目 | 現在の設定 |
|---|---|
| C71内の保存上限 | 40 GiB |
| C71に残す空き容量 | 8 GiB |
| 1回の暗号化ファイル | 最大8 GiB |
| 1回の元データ | 最大50 GiB、10万ファイル・10万フォルダ |
| 保存方式 | 毎回全体を保存。差分・重複排除なし |

USB受渡しと復元書き出しの際には、一時的に暗号化ファイル1個分の追加容量が必要です。PCにも暗号化・復元用の一時領域が必要です。

不要な版はC71の「保存一覧・重要指定・個別削除」で選び、端末のPIN等で認証して削除します。PCから削除するAPIはありません。容量不足時は新規保存を拒否し、旧版を保持します。

### 保持ルールと重要指定

C71の「保持ルールで整理候補を確認」で、次のルールから外れる版だけを候補にします。**候補の選択→削除内容の確認→端末認証**を経て削除します。時間経過や容量不足だけでは削除しません。

| 保存日からの期間 | 保持する版 |
|---|---|
| 直近30日（今日を1日目） | 全版 |
| 31～180日 | 対象ごとに、その日の最新版 |
| 181日～1年未満 | 対象ごとに、月曜始まりの週の最新版 |
| 1年以上（前年の同日以前） | 対象ごとに、その月の最新版 |
| 重要指定 | 期間に関係なく全て保持 |

対象フォルダごとに分けて計算し、対象ごとの最後の1版も必ず保持します。Windowsの対象フォルダの絶対パスから識別子を作るため、場所を変更すると別対象になります。時刻はC71での保存日時を使い、整理の暦のタイムゾーンは初回に固定します。未来の日時の版は保持します。

0.1で保存した版には対象識別子がないため、整理候補にしません。個別確認して削除してください。重要指定はC71の「保存一覧・重要指定・個別削除」から行います。重要を解除する際にも端末認証が必要です。実行直前にルールと重要指定を再計算します。

### 空き容量の通知

初期値は**端末の空き容量15%未満で「整理が必要」**です。「空き容量の警告しきい値」で1～50%に変更できます。分母は端末のアプリ保存先ファイルシステムの容量です。40GiBのアプリ上限とは別です。警告から削除処理を呼ぶことはありません。

## 追加方式：4色・バイナリ・まとめACK（0.3.0）

従来の白黒・512バイト方式に加え、次の方式を選べます。

- 1画面の実データは最大 **1,024バイト**。JSONとBase64の二重変換を使わず、バイナリ形式に署名します。
- 2枚のQRのビット面を白・黒・赤・シアンの **4色** に重ねます。専用デコーダで2層を復元し、同じパケットの組であることを確認します。
- 最大 **8枚** を順に表示し、受信状況をビットマップのACKでまとめて返します。欠けた番号だけを再送します。
- 戻りは白黒QRの署名付きACK・状態通知だけです。保存完了は全体の保存・読み戻し照合後に限ります。

PCの「光学でバックアップ」で方式を「追加：4色・1,024 bytes・まとめACK」にし、C71で「4色光学受付」を開きます。従来方式は両側で従来の項目を選べば使用できます。初回登録と復元鍵の保管には引き続きUSBを使います。

4色の1枚表示時間は初期値1秒、0.2～3秒で指定できます。表示時間は転送速度の保証ではありません。最初は1秒以上で、コード全体が映るように調整してください。容量上限は暗号化後16MiBのままです。

新方式は本プロジェクト独自形式で、HCC2D・JAB Code互換ではありません。詳細は [OPTICAL_V2.md](OPTICAL_V2.md)、実機で確認できた範囲は [VALIDATION.md](VALIDATION.md) を参照してください。

## 従来方式：白黒の光学バックアップ

初回の端末・PC登録と復元鍵の保管はUSBで行ってください。光学は**PC画面→C71前面カメラの暗号化データ**、**C71画面→PCカメラの署名付きACK・状態通知**に限定します。光学側にファイル書き出し・復元鍵回収・削除・一覧取得のAPIはありません。復元にはUSBを使います。

1. PCで対象フォルダと保管済みの復元鍵を選びます。
2. C71で「光学受付（PC → C71）」を開きます。USB受付は停止します。
3. PCで「光学でバックアップ」を開き、カメラ番号を選んで「光学送信開始」を押します。
4. C71の前面カメラがPCのQRを読み、PCカメラがC71のACKを読めるように、画面同士を向かい合わせます。反射を避け、両方のQR全体が映る距離に調整してください。
5. ACKを読めるまで同じQRを表示します。最終的な保存・読み戻し照合と署名付き最終ACKの確認後にだけ完了表示します。

光学は512 bytesずつ送る方式で、暗号化後16MiBを上限にしています。USBより大幅に低速で、速度はカメラ・距離・照明に依存します。大容量バックアップにはUSBを使ってください。途中で終了すると未完了になります。完了直前にACKを失った場合は保存済みの可能性があるため、USBの履歴で確認してください。

光学モードはアプリのプロトコルで戻りデータを限定しています。侵害されたOSまで含めて逆方向通信を物理的に阻止する装置ではありません。

## 安全性の範囲

AES-256-GCMで文書を暗号化し、復元鍵はRSA-OAEPで包んでC71の専用領域に保管します。鍵を開く秘密鍵はAndroid Keystoreに置き、端末認証を要求します。ただしアプリのアンインストール・データ消去、端末初期化・故障・紛失、画面ロック無効化等によるKeystore鍵の失効には備えが必要です。独立した鍵のコピーとバックアップも保持してください。

保存名・容量・日時・鍵ID等の管理情報は転送フォルダで見えます。保存名に機密情報を含めないでください。詳しくは [SECURITY.md](SECURITY.md)、検証範囲は [VALIDATION.md](VALIDATION.md) を参照してください。

## 接続できない場合

- C71のロック解除、USBのファイル転送、アプリの受付中表示を確認します。
- 充電専用でないデータ通信ケーブルを使います。
- 複数の対象Android端末が接続されている場合、使用する1台だけにします。
- アプリの再インストール等で署名鍵が変わるとWindowsは接続を拒否します。端末側の状態を確認した上で、Windowsアプリ終了中に `%LOCALAPPDATA%/C71Vault/device.json` を退避し、再登録します。鍵変更の原因が不明な場合は登録し直さないでください。
- 復元鍵は再発行できません。C71に保管済みなら端末認証で回収できます。PCとC71の両方から鍵を失うと復元できません。
- `Documents/C71Vault` は受渡し専用です。他の資料を置かないでください。失敗した転送の一時ファイルを整理する際は双方の処理を停止してください。保管済みの本体はこのフォルダにはありません。
